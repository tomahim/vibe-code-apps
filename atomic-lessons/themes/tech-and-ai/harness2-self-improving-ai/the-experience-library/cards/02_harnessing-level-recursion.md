Here is the loop's shape. While a task is being refined, the improvement harness, the editor roles, prompts and decision rules that guide refinement, stays fixed. After the task returns its deliverable, the pipeline reviews the complete improvement record: reference executions, candidate harnesses and their probes, composition decisions and the selected result. From this record, reflection extracts lessons about which changes addressed which observed deficiencies, under what conditions, with what consequences.

Then the update: the adopted harness and the supported lessons go into a persistent harness improvement library, organized per domain. The next task starts from the same common base harness as always, but its refinement is now guided by the updated improvement harness, which can consult everything the library holds. Model weights, stage instructions and the decision rule never change; only the library evolves. That is the sense in which the system learns how to improve.
