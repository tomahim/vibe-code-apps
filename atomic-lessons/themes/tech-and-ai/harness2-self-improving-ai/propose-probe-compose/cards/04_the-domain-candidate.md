The domain editor owns the subject matter the invariant editor is forbidden to touch: the knowledge, procedures and constraints of this kind of work. Its most interesting instruction concerns verified workspace facts. When the base executions establish something concrete, which key columns join two files, which entries have no counterpart, what units a field uses, the editor should write the fact itself into the harness, anchored as a workspace fact, rather than merely writing a procedure for rediscovering it.

Why write the fact? Because a rule telling the agent how to find a mapping leaves the hardest step to the agent; the mapping itself removes it. But facts are held to a strict standard: record only what the evidence actually establishes, because a guessed fact is worse than none. Procedures, by contrast, are written for the domain broadly, since the harness may be stored in the domain's library where later tasks read it as an example. Scoped too narrowly, procedure would be wrong for a different task in the same domain.
