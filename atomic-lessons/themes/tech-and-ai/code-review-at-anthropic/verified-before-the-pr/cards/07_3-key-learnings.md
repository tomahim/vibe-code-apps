Most review now happens before a pull request exists. Give the agent something it can run and demand the output: tests, a build, a lint run, or a screenshot against the design. Boris Cherny estimates verification makes the final result two to three times better, and it looks different in every domain.

When the reviewer flags the same thing repeatedly, fix the source in a skill, a lint rule, or the instructional files. CLAUDE.md tells Claude what the project is and stays short; REVIEW.md tells the reviewer what failure looks like in each area, caps nits, and demands file-and-line evidence.

Agent review quality is a context problem. The same agent performs like a careful colleague or a confident intern depending on the instructions, checks, and evidence requirements you put in front of it.
