When someone wants to understand a part of the codebase, they ask Claude to write an explainer for exactly that slice. The explainer takes minutes to produce, and unlike a wiki page it reflects the code as it is today, because it is generated from the code at the moment of the question.

The example in the article is concrete: how does Claude Code retrieve managed settings? That is the kind of question a newcomer burns an afternoon on, tracing calls across files. An explainer compresses the afternoon into minutes and points at the real code. Some engineers go a step further and have Claude build a small artifact that visualizes that part of the code and teaches it the way that person likes to learn. Personalized, current, disposable: the opposite of the outdated architecture document nobody trusts.
