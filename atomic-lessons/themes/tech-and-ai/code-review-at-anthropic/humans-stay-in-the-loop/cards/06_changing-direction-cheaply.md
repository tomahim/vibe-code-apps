title: Changing direction cheaply
archived: false
---
Because agents make it cheap to start things, some work should not land, and the team has a norm for that too. Usually someone in the channel asks why, points at an earlier decision, or suggests a simpler route, and the author closes or reshapes the pull request.

Two details make this work culturally. First, since the code was fast to write, closing the pull request does not feel like a loss; nobody is defending a week of sunk effort. Second, the trick is to raise a different direction in the thread early, not as a blocking comment on a finished pull request. Early redirection is cheap and collegial; late redirection feels like a veto. Together these norms are the social layer of the same principle the technical layers embody: make being wrong cheap, and people will let go of bad directions without a fight.
