How Music generation library works

A real SuperCollider engine running inside the browser tab, driven by JavaScript you can edit. Six steps, each one an interactive view of the actual code in the app (/apps/music-library, PR #383).

One note, from text to speaker

Nothing runs on a server. The music is JavaScript text in the editor. Pressing Play turns that text into timestamped messages for SuperCollider's synthesis engine, compiled to WebAssembly and running on the browser's audio thread. Tap Send a note through to follow one bell.

The editor language is plain JavaScript against a small music API (m.play, m.chord, m.sleep, m.spawn). It is not SuperCollider's own language (sclang). What is SuperCollider is the sound engine: scsynth.

Waking the engine

The first tap on Play boots everything. Browsers refuse to start audio without a user gesture, so boot is tied to that tap. Step through engine.boot() and watch the node tree appear.

The music API in 6 lines


m.play("prophet", {note:"C3", attack:2, dur:6, release:3})
m.chord("blade", ["A2","E3","B3"], {dur:10})
await m.sleep(4)               // move this layer's clock
m.spawn(async (m) => { ... })  // new concurrent layer
while (m.playing) { ... }      // loop until Stop
m.choose([..]) m.rrand(a,b) m.note("F#3") m.notes("C3 E3")

      
Each m.spawn creates a layer with its own musical clock, starting from where its parent was. Neon Rain has four: a drone, a pad, random bells, a distant growl. Time is only ever moved by await m.sleep(...).

      
Source: tracks/neon-rain.js, tracks/first-light.js, engine/player.js

    

  







  
Why the timing stays tight

  
JavaScript timers wobble. Audio must not. So the code never says "play now". It runs about one second ahead of the sound and stamps every note with the exact moment it must start. The engine then starts it on that exact audio sample.

player.js + supersonicEngine.js scheduleNote

  

  
Blue notes are sent and waiting inside the engine. Hollow notes are still only in the JS loop. If a note is sent after its own timestamp it turns red: that is the failure the one-second margin protects against. The sliders are a simulation of the idea. The app uses a fixed 1.0 s lookahead and a 0.4 s delay before the first note.

Stop, precisely


supersonic.send("/clearSched");           // drop pending notes
supersonic.send("/g_freeAll", sourceGroup); // free only the notes

      
The reverb and master level live in a separate group and keep running, so the next Play starts instantly. During development an extra group id of 0 in that command emptied the whole root group, effects included. That bug is fixed in the shipped code.

    
Where your edits live

      
Each track's code is saved in the browser's localStorage under music-library:code:<track id>, on your device only. Editing while playing shows "press Play again": the running music is the code as it was at Play.
