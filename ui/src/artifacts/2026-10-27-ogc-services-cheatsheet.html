OGC Services Cheatsheet

OGC is the Open Geospatial Consortium, the body that writes the open standards behind web maps, geodata services and sensor feeds. Below: each legacy "OWS" service, its newer OGC API counterpart, and example requests for both. Each request is labelled TESTED (run against a public server on 27 Oct 2026) or ILLUSTRATIVE (right shape, placeholder host, not run). Tap any highlighted parameter to see what it does.

Legacy: OGC Web Services (OWS)

One endpoint per service, verbs in the query string: ?SERVICE=WMS&REQUEST=GetMap. Discover with GetCapabilities (a big XML document). Mostly XML replies, GML for features, and a lot of CRS and axis-order traps.

Still everywhere: GeoServer, MapServer, QGIS Server, ArcGIS Server, national SDIs (INSPIRE).

New: OGC API family

Resource-oriented URLs and plain HTTP: /collections/{id}/items?bbox=.... JSON first, described by OpenAPI, with a landing page, /conformance and /collections instead of GetCapabilities. Built from shared "building blocks" so parts combine.

Implementations: pygeoapi, GeoServer, MapServer, pg_featureserv, ldproxy and others. Which parts each supports varies.

Reading the mappings

A newer API is not always a 1:1 replacement. direct covers the same job. partial covers some of it. no twin means new ground or no single successor.

New ground: OGC APIs with no legacy twin

Environmental Data Retrieval (EDR)

Query a data cube by position, area, radius, cube, trajectory, corridor or locations. See card 9. Published (v1.2)

Discrete Global Grid Systems (DGGS)

Access data organised on a global hierarchical grid of zones. Part 1 approved Oct 2025

Moving Features

Trajectories of things that move as rigid bodies (ships, vehicles, drones). Part 1 approved Oct 2025

Connected Systems

Sensors, platforms, actuators, deployments, observations and commands. Covers part of what SOS did. Parts 1 and 2 published

3D GeoVolumes and Routes

3D content by volume of space, and route requests independent of the routing engine. No "Approved Standard" badge on ogcapi.ogc.org

Traps that waste an afternoon

Axis order

  • WMS 1.3.0 with CRS=EPSG:4326 wants BBOX=minLat,minLon,maxLat,maxLon. The request on card 2 uses this and returns a correct world map.
  • Want lon,lat? Use CRS=CRS:84.
  • OGC API bbox is minLon,minLat,maxLon,maxLat (CRS84) unless you pass bbox-crs.

Renamed parameters

  • WMS 1.1.1 to 1.3.0: SRS becomes CRS, X/Y become I/J.
  • WFS 1.x to 2.0: TYPENAME becomes TYPENAMES, MAXFEATURES becomes COUNT, and STARTINDEX pages.

Paging and formats

  • OGC API: follow the rel="next" link in the response instead of computing offsets.
  • f=json is a convenience many servers offer (pygeoapi does). The portable way is the Accept header.

Check what the server supports

  • Legacy: read GetCapabilities (layers, formats, CRS, limits).
  • OGC API: read /conformance and /collections/{id}. Optional parts such as CQL2 filtering, CRS or tiles only work if listed there.
  • Property selection and sorting on Features are still drafts, so some servers differ.
